سه‌بعدی / WebGL / کارایی

کارایی در سایت سه‌بعدی؛ WebGL بدون قربانی‌کردن تجربه کاربر

تجربه سه‌بعدی خوب فقط زیبا نیست؛ باید روی دستگاه واقعی سریع، قابل تعامل و قابل کاهش باشد.

روژان بهروزی۱۲ مهر ۱۴۰۵یادداشت‌های ROZNEX

قبل از مدل‌سازی بودجه کارایی تعریف کن

در وب سه‌بعدی، تصمیم‌های کارایی باید قبل از ساخت فایل گرفته شوند. تعداد چندضلعی، اندازه بافت، تعداد متریال، نور، پردازش پس از رندر و رفتار دوربین همگی روی CPU، GPU و شبکه اثر دارند.

اگر بخش اصلی سه‌بعدی مهم‌ترین عنصر صفحه است، باید بدانیم روی موبایل چه چیزی واقعاً لازم است و چه چیزی می‌تواند کاهش پیدا کند یا با تصویر/ویدیو جایگزین شود.

همه چیز را در اولین نمایش اولیه بارگذاری نکن

منابع پایین صفحه لازم نیست همزمان با محتوای بالای صفحه دانلود و پردازش شوند. web.dev برای کارایی روی تعویق و بارگذاری تنبل منابع غیرضروری تأکید دارد. همین اصل برای بافت، مدل ثانویه و بخش‌های تعاملی سه‌بعدی هم مهم است.

LCP را قربانی WebGL نکن

اگر بوم رندر یا فایلهای سه‌بعدی باعث شوند متن و تصویر اصلی دیر ظاهر شوند، Hero از نظر تجربه کاربر شکست خورده است. یک تصویر جایگزین سبک می‌تواند خیلی سریع نمایش داده شود و صحنه اصلی بعد از آماده‌شدن جای آن را بگیرد.

نسخه جایگزین موبایل یک شکست نیست

کم‌کردن هندسه، خاموش‌کردن پردازش پس از رندر یا استفاده از تجربه دوبعدی جایگزین در موبایل به معنی کم‌ارزش‌کردن پروژه نیست. هدف این است که داستان اصلی روی دستگاه واقعی کار کند.

تعامل نباید رشته اصلی را قفل کند

ردیابی اشاره‌گر، اسکرول و انیمیشن‌های متعدد اگر بدون محدودیت اجرا شوند، تعامل را سنگین می‌کنند. کاربر باید بتواند اسکرول، لمس و ناوبری را بدون رقابت با حلقه رندر انجام دهد.

اندازه‌گیری روی دستگاه واقعی

Performance سه‌بعدی را فقط روی لپ‌تاپ توسعه‌دهنده نسنج. حداقل یک گوشی میان‌رده، شبکه کندتر و حالت کاهش حرکت را بررسی کن. Core Web Vitals هم باید در کنار FPS دیده شوند.

منابع: web.dev Performance و طراحی واکنش‌گرا.

جمع‌بندی: تجربه سه‌بعدی حرفه‌ای آنی نیست که بیشترین افکت را داشته باشد؛ آنی است که در دستگاه واقعی، داستان را بدون قربانی‌کردن سرعت و تعامل منتقل کند.
