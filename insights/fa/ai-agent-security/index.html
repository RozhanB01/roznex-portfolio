امنیت AI Agent؛ سطح دسترسی، ابزار و Human-in-the-loop

وقتی مدل اجازه اقدام دارد، امنیت دیگر مسئله Prompt نیست؛ مسئله معماری دسترسی و کنترل ابزار است.

Rozhan Behrouzi۱۲ مهر ۱۴۰۵ROZNEX Insights

ایجنت را مثل یک کاربر دارای دسترسی ببین

وقتی مدل می‌تواند ابزار صدا بزند، فایل بخواند، داده تغییر دهد یا ایمیل بفرستد، مسئله دیگر فقط کیفیت پاسخ نیست. ایجنت به یک Actor نرم‌افزاری تبدیل می‌شود و باید همان‌قدر جدی با Permission، Audit و محدودیت آن برخورد کرد.

Least Privilege برای Toolها

هر ابزار فقط باید کمترین دسترسی لازم برای همان جریان کاری را داشته باشد. ایجنت گزارش‌ساز اگر فقط نیاز به خواندن دیتابیس دارد، نباید اجازه حذف یا Update عمومی داشته باشد. Authorization هم نباید بر اساس متن تولیدشده توسط مدل تصمیم بگیرد.

ورودی خارجی قابل اعتماد نیست

محتوای وب، ایمیل، PDF یا پاسخ API می‌تواند دستور مخرب یا داده گمراه‌کننده داشته باشد. ورودی باید Validate و Sanitise شود و مرز «داده» و «دستور» تا حد ممکن روشن بماند.

Human-in-the-loop برای اقدام پرریسک

OWASP توصیه می‌کند عملیات پرریسک یا غیرقابل برگشت بدون نظارت انسانی انجام نشوند. این می‌تواند انتقال وجه، حذف اطلاعات، تغییر Permission یا ارسال پیام مهم به مشتری باشد.

Memory و داده حساس

حافظه ایجنت نباید به سطل اطلاعات حساس تبدیل شود. Context بین کاربران باید جدا باشد، داده حساس Redact یا رمزگذاری شود و Logها نباید Credential یا اطلاعات شخصی را بی‌دلیل ثبت کنند.

Limit برای Loop، Cost و Tool Chain

ایجنتی که می‌تواند بی‌نهایت Retry کند یا زنجیره ابزار نامحدود بسازد، هم ریسک هزینه دارد و هم ریسک رفتار خارج از کنترل. سقف زمان، تعداد ابزار، Retry و Budget باید بخشی از معماری باشد.

قبل از Production حمله را شبیه‌سازی کن

Prompt injection، داده آلوده، پاسخ API غیرمنتظره، خطای Permission و رفتار Tool failure باید عمداً تست شوند. تغییر مدل یا ابزار هم می‌تواند سطح ریسک را عوض کند و نیاز به Regression test دارد.
